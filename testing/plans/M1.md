# M1 — Connect and browse: test plan

Scope from `docs/ARCHITECTURE.md` section 10: direct gNMI and one jump host;
Capabilities; YANG from a local folder; schema tree with search; Get on a node; copy as
JSON/YAML; `gnmic get`/`subscribe` generation.

Case IDs are stable. New cases get new numbers; removed cases are marked `retired`,
never renumbered. Run on **both macOS and Windows** where marked `[mac+win]`.

Who runs what:
- `[cli]`: the agent runs it alone through the CLI with `--output json`.
- `[ui]`: needs the human in the browser (rendering, clipboard, responsiveness).
- Unmarked: run via the CLI where a command exists, otherwise in the UI.

## CLI

| ID | Case | Expected |
|---|---|---|
| M1-CLI-01 `[cli]` `[mac+win]` | `canopy version --output json` | Valid JSON with version, commit, build date, `schemaVersion` |
| M1-CLI-02 `[cli]` | `canopy connect --target … --output json` against a lab device | Exit code 0; JSON lists models, encodings and gNMI version, matching `gnmic capabilities` |
| M1-CLI-03 `[cli]` | Same with a wrong password | Exit code 2; JSON error with a code; no password in output or log |
| M1-CLI-04 `[cli]` | `canopy get … --output json` on a valid but unconfigured path | Exit code 0 with empty result, or exit code 3 with the gRPC code; never a generic failure |
| M1-CLI-05 `[cli]` | Any command with `--non-interactive` and an unknown jump-host key | Fails immediately with the fingerprint in the JSON error; no prompt |
| M1-CLI-06 `[cli]` | `canopy tree --yang <dir> --find <leaf> --output json` | All matching paths with module and kind |
| M1-CLI-07 `[cli]` | `--log-level debug --log-file x.log` on any command | Structured JSON log lines; no secrets

## Connection

| ID | Case | Expected |
|---|---|---|
| M1-CONN-01 | Connect directly to a lab device with TLS skip-verify | Connected; Capabilities shown (models, encodings, gNMI version) |
| M1-CONN-02 | Connect with plaintext to a device that requires TLS | Clear error naming TLS as the likely cause; no hang longer than the timeout |
| M1-CONN-03 | Connect with a wrong password | Clear authentication error; password not shown in UI or logs |
| M1-CONN-04 `[mac+win]` | Connect through one SSH jump host using the SSH agent | Connected; no local port opened (check with `netstat`/`lsof`) |
| M1-CONN-05 `[mac+win]` | Same as 04 with a key file with passphrase | Passphrase prompt in the UI; connected |
| M1-CONN-06 | Jump host with an unknown host key | Asked to trust the key, showing its fingerprint; refusing aborts the connection |
| M1-CONN-07 | Jump host defined only in `~/.ssh/config` (`HostName`, `User`, `IdentityFile`) | Settings picked up from the config |
| M1-CONN-08 | Unreachable device | Error within the configured timeout; UI stays responsive |
